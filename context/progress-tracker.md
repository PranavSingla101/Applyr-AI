- AI-1 All AI calls moved from OpenAI to Groq (2026-08-29): reported bug — "Generate Resume from Profile" always failed with "Failed to generate resume content." Root cause was not code: replaying the route's exact request against the real key returned `429 You have no credits remaining` from OpenAI, on every model and parameter variant. Since all three AI call sites share that one account, resume extraction (Feature 07) and job scoring (Feature 10) were equally dead — Feature 10's never-yet-run search would have failed the same way. Developer chose Groq. New `lib/ai.ts` holds the single client factory (`createAIClient()` — the `openai` SDK pointed at `https://api.groq.com/openai/v1`, so no new dependency), `AI_MODEL`, `AI_MAX_COMPLETION_TOKENS`, and the `jsonSchemaFormat()`/`aiObject()`/`AI_STRING` schema helpers; `agent/matcher.ts`, `app/api/resume/extract/route.ts` and `app/api/resume/generate/route.ts` all go through it, and `GROQ_API_KEY` was added to `.env.local`. **Model is `openai/gpt-oss-20b`** — the Llama ids in Groq's public docs (`llama-3.3-70b-versatile`, `llama-3.1-8b-instant`) return 404 on this account, so the model was picked from a live `models.list()` rather than the docs. **Three things the live probes caught that a straight key-swap would have shipped broken:** (1) **The matcher returned `matchScore: 0.75`, not 75.** `clampScore()` rounded that to 1, which would have scored every job 1/100 and made the whole matching feature meaningless while looking like it worked. Fixed in the prompt (explicit "whole number on a 0-100 scale, never a fraction or a 0-1 ratio") *and* defensively in `clampScore()`, which now treats a non-integer value in (0, 1] as a ratio and scales it. (2) **Token budgets were far too small.** `gpt-oss-20b` is a reasoning model and bills hidden reasoning tokens against `max_completion_tokens`; the matcher's 300 left ~30 tokens of headroom, so budgets are now 800 (matching), 2000 (extraction), 2500 (generation). _Add notes here as the build progresses — workarounds, patterns, anything that differs from the context files._

- `@react-pdf/renderer` was listed in `code-standards.md`'s approved dependencies since Feature 05/06 planning but was never actually installed — `npm install @react-pdf/renderer` was required during Feature 08 before it could be imported. Its `renderToBuffer`/`Document` types require the element passed in to be typed as `ReactElement<DocumentProps>` specifically; a wrapper component (like `lib/pdf/ResumeDocument.tsx`) whose root JSX is `<Document>` still needs an explicit cast at the call site (`app/api/resume/generate/route.ts`) since TS doesn't structurally trace through a function component's return type.
- `@insforge/sdk`'s `storage.upload()` only accepts `(path, file: File | Blob)` — no third options argument, despite `library-docs.md`'s example showing `{ contentType, upsert }`. To upload a raw `Buffer` (e.g. a PDF rendered server-side, not a browser `File`), wrap it in `new Blob([new Uint8Array(buffer)], { type: "application/pdf" })` first.
